The order for every session is fixed: register, commit the registry, capture, close, commit the registry and the session evidence. The tool refuses to start a capture whose registration event is not in the committed registry, and refuses to compute a verdict from a registry that has a broken chain or an event not present in the committed file. A session counts from its registration, so one that was registered and never closed counts. Each session report carries the hash of its registration event and a started marker written before the first capture. Kinds: `smoke` (one profile pair proving only that both arms load and sample; it writes structure and load facts and no timing value or comparison; at most one per source identity unless the previous one failed structurally; refused once a calibration or qualifying entry exists for the identity; never counts); `calibration` (exactly one per source identity, does not count toward the cap because it contains no candidate arm, but gates qualifying sessions as in section 6); `qualifying` (candidate against reference; every started one counts, whatever its outcome, at most 3 per source identity). The result is always worded with its denominator. Host facts (power plan, heavy applications, CPU load) are recorded before and after every session (O-4).
