## Standing fragility found while checking this: frozen hashes cover working-tree bytes

Read-only comparison on 2026-10-09 (`git config core.autocrlf` is `true`; the root `.gitattributes` pins only `src/builders/enemyGLTF.test.js`), for the 127 file entries of `referenceIdentities` (the 128th is the sampler function), of the frozen hash against the on-disk file, the committed blob, and the blob with every line ending as CRLF:

| Group | Count | What reproduces the frozen hash |
|---|---|---|
| Frozen hash equals the committed blob | 38 | any checkout that does not convert, and for binary files every checkout |
| Frozen hash equals only the all-CRLF form of the blob | 57 | a Windows checkout with `core.autocrlf=true`; not an LF checkout |
| Frozen hash equals only the current mixed-ending working file | 25 | nothing but this working copy: no git object and no checkout |
| On-disk file already differs from the frozen hash | 7 | the five permitted mutable owners, the CR-02 publication and `enemyGLTF.test.js`, all expected |

`src/main.js` is in the group of 25, together with `index.html`, `style.css` and 22 other `src/` files: its working file has 359 CRLF and 206 LF line ends; the frozen hash `c7620446...882d3` is of those bytes; the committed blob hashes to a different value. Any git operation that rewrites one of those 25 files (checkout, stash, reset, renormalise) would make the frozen gate throw `Protected source changed` for it with no way to get the bytes back. So 82 of 127 identities depend on line endings and 25 are irreplaceable.

This plan does not try to repair the frozen gate's hashing. It does three bounded things: preserves the 25 irreplaceable byte sequences before touching anything (task 1), keeps its own exception sound against this (tasks 2 and 3), and puts the fragility in front of the owner (checkpoint) and in the SUMMARY as a recorded limitation.

Effect on the paired gate: plan 07-16 as first written built its reference arm with `git archive`, whose bytes for these files differ from the working tree that serves the candidate arm, so its "refuse any other difference between the arms" rule would have refused dozens of files that did not change. Plan 07-16 is corrected in this revision to copy working-tree bytes for every file outside the five owners, and the plan 07-15 review is asked to confirm it.
